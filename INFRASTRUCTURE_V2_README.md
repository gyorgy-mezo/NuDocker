## 🚀 Quick Start
### Prerequisites
- HUN-REN Cloud account with API access
- Terraform >= 1.0
- Packer >= 1.8
- Ansible >= 2.12
- SSH key at `~/.ssh/id_rsa`
### One-Command Deployment
```bash
cd infrastructure
./deploy-v2-improved.sh all
```
**Deployment time**: 60-90 minutes (fully automated)
### Phase-by-Phase Deployment
```bash
# Build base image (30-45 min)
./deploy-v2-improved.sh packer
# Deploy infrastructure (10-15 min)
./deploy-v2-improved.sh terraform
# Configure cluster (20-30 min)
./deploy-v2-improved.sh ansible
# Validate deployment (2-5 min)
./deploy-v2-improved.sh validate
```

## 🎓 Usage Examples
### Access the Cluster
```bash
# SSH to central manager
ssh -i ~/.ssh/id_rsa ubuntu@<FLOATING_IP>
```

```bash

condor_history -limit 10
```

```bash

cd /storage/slurm_jobs
```

## 🔍 Proven Patterns from htcondor-slurm-demo
All patterns have been **validated in production** on HUN-REN Cloud (August 24, 2025):
### 1. Network Port Pattern (Terraform)
**Problem Solved**: Floating IP association failures in original version
**Pattern**:
```hcl
resource "openstack_networking_port_v2" "central_manager_port" {
  network_id = data.openstack_networking_network_v2.default.id
  security_group_ids = [openstack_networking_secgroup_v2.nudocker_sg.id]
}
resource "openstack_networking_floatingip_associate_v2" "assoc" {
  floating_ip = openstack_networking_floatingip_v2.fip.address
  port_id     = openstack_networking_port_v2.central_manager_port.id
}
```
**Validation**: ✅ Working in htcondor-slurm-demo production (8 nodes deployed)
### 2. Security Group Pattern (Terraform)
**Problem Solved**: Terraform drift when using explicit port ranges
**Pattern**:
```hcl
resource "openstack_networking_secgroup_rule_v2" "internal_all" {
  direction       = "ingress"
  protocol        = "tcp"
  # Omit port ranges when using remote_group_id - OpenStack stores as "all ports"
  remote_group_id = openstack_networking_secgroup_v2.nudocker_sg.id
}
```
**Validation**: ✅ No drift in htcondor-slurm-demo after multiple terraform apply cycles
### 3. Unified Image Approach (Packer)
**Problem Solved**: Complex multi-image management
**Pattern**: Single base image with all software, node roles configured by Ansible
**Validation**: ✅ htcondor-slurm-demo uses single image for CE, central manager, execute, and SLURM nodes
### 4. SSH Key Distribution (Ansible)
**Problem Solved**: Manual SSH key setup across cluster
**Pattern**: Generate key on central manager, distribute automatically via Ansible
**Validation**: ✅ Working in htcondor-slurm-demo site.yml (all nodes accessible)
### 5. Munge Key Sharing (Ansible)
**Problem Solved**: SLURM authentication setup
**Pattern**: Create munge key on controller, slurp and copy to compute nodes
**Validation**: ✅ SLURM cluster operational in htcondor-slurm-demo (3 compute nodes)

## 🔧 Configuration
### Terraform Variables
Edit `terraform/terraform.tfvars`:
```hcl
key_pair             = "alma"              # Your SSH key pair name
external_network     = "ext-net"           # External network for floating IP
cluster_name         = "nudocker"          # Cluster name prefix
execute_node_count   = 5                   # HTCondor execute nodes
slurm_compute_count  = 3                   # SLURM compute nodes
```
### Resource Scaling
To change cluster size:
```bash
cd infrastructure/terraform
vim terraform.tfvars
# Increase execute nodes:
execute_node_count = 10    # 80 vCPU for HTCondor
# Increase SLURM nodes:
slurm_compute_count = 5    # 40 vCPU for SLURM
# Apply changes
terraform plan
terraform apply
```

## 🐛 Troubleshooting
### Common Issues
**Issue**: Packer build fails with "Image not found"
**Solution**: Base image UUID is hardcoded for HUN-REN Cloud Ubuntu 22.04 LTS
**Issue**: Terraform floating IP association fails
**Solution**: This is why we use the network port pattern! v2.0 fixes this.
**Issue**: Ansible cannot connect to instances
**Solution**: Script waits for SSH (30 attempts × 10 sec). Check security group allows SSH from your IP.
**Issue**: HTCondor execute nodes not appearing in pool
**Solution**: Check pool password, verify CONDOR_HOST setting, restart condor service
**Issue**: SLURM nodes in DOWN state
**Solution**: Check munge key distribution, verify slurmd service, restart if needed
For complete troubleshooting guide, see [INFRASTRUCTURE_IMPROVEMENTS_V2.md](INFRASTRUCTURE_IMPROVEMENTS_V2.md#troubleshooting)

## 🔐 Security Considerations
**Network Isolation**:
- Only central manager has public IP
- All other nodes on private network
- Internal communication via security group rules
**Authentication**:
- SSH key-based authentication
- HTCondor pool password
- SLURM munge authentication
- NFS access control
**Best Practices**:
- Change default pool password in Ansible playbook
- Restrict SSH access by IP if possible
- Regular security updates via `apt upgrade`
